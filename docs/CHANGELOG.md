# История изменений

**Tags:** #bitrix24 #changelog #версии

## 1.9.2 (текущая)

- **Строки списка порталов в popup переверстаны.** Длинные адреса больше не ломаются по символам — origin выводится в одну строку с многоточием (полный адрес — в `title` по наведению). Кнопки «Изменить»/«Удалить» заменены компактными иконками (карандаш/корзина), освобождая место под адрес.
- Делегирование клика по «Удалить» переведено на `closest()` — корректно ловит клик по SVG внутри кнопки.

---

## 1.9.1

- **Исправлено: добавленный через popup портал не сохранялся.** При вызове `chrome.permissions.request()` из popup Chrome закрывает окно на время системного диалога разрешений — callback со `storage.set`/регистрацией скрипта выполнялся в уничтоженном контексте и не отрабатывал. Финализацию перенёс в service worker (`chrome.permissions.onAdded`): запись в список порталов и регистрация content-скрипта теперь переживают закрытие popup.
- **Весёлая подпись вместо «портал уже добавлен».** Когда текущий портал в списке — popup показывает «🎉 Текущий портал добавлен в расширение!» и прячет кнопку «Добавить текущий портал».
- **Live-обновление списка порталов** в popup и на странице настроек через `chrome.storage.onChanged` — список появляется без переоткрытия экрана.

## 1.9.0

- **Переключатель темы интерфейса «Авто / Светлая / Тёмная».** Сегмент-контрол в шапке popup и страницы настроек. «Авто» (по умолчанию) следует за системной темой ОС; «Светлая»/«Тёмная» — принудительный выбор. Сохраняется в `chrome.storage.local` (`bpUiTheme`), применяется на обоих экранах.
- **`theme.js`** — общий скрипт: рано применяет тему (атрибут `data-theme` на `<html>`) и проводит кнопки переключателя. Подключается первым в `<head>` обоих экранов.
- **`tokens.css`:** тёмные токены теперь срабатывают и по `[data-theme="dark"]` (ручной выбор), и по `@media (prefers-color-scheme: dark)` для режима «Авто» (через `:root:not([data-theme])`). Переключение логотипа чёрный/белый централизовано здесь же.
- **Сноска «Остальные наши модули и решения смотрите [на сайте](https://5corners.ru/resheniya_i_moduli/)»** — в подвале popup и страницы настроек.

## 1.8.1

- **Полные настройки открываются отдельной вкладкой** (`options_ui.open_in_tab: true`). Раньше Chrome рендерил их во встроенном узком модальном окне на `chrome://extensions`, из-за чего таблица цветов не помещалась и появлялся горизонтальный скролл. Теперь — полноширинная страница.
- Контейнер настроек расширен (`.page` max-width 880 → 1280px).

## 1.8.0

- **Полный редизайн интерфейса popup и страницы настроек.** Современный вид: карточки, switch-тумблеры на базе `<input type="checkbox">`, выраженная типографика, мягкие тени, светлая и тёмная темы (через `@media (prefers-color-scheme: dark)`).
- **Единые дизайн-токены** — `tokens.css` (CSS custom properties: поверхности, границы, текст, статусы, радиусы, тени, типографика, отступы). Подключается первым и в popup, и в options; `popup.css`/`options.css` ссылаются только на переменные.
- **Стили options вынесены** из inline `<style>` в отдельный `options.css`.
- **Фирменный знак 5 УГЛОВ в шапке** обоих экранов — `icons/logo-black.png` (светлая тема) / `icons/logo-white.png` (тёмная), переключение по `prefers-color-scheme`.
- **`options.js`:** одиночный тумблер `#global-enabled` заменён на те же 4 пофичевых `data-tool`-тумблера, что в popup (синхронизация настроек инструментов между экранами).
- Технические ограничения соблюдены: без сборки, без CDN/внешних ресурсов, системный шрифтовой стек, иконки — inline SVG; DOM-контракт (id/классы/`data-tool`), к которому привязан JS, сохранён.

## 1.7.0

- **Пофичевые тумблеры на главной (popup).** Вместо единственного «Включить подсветку синтаксиса» — отдельные переключатели для каждого инструмента: подсветка синтаксиса, поиск в списках и полях, поиск по нодам, подсветка нод с ошибками. Каждый инструмент можно включить/выключить независимо.
- **`content.js`:** убран глобальный ранний `return` по `bpSyntaxEnabled` — теперь каждая фича гейтится своим флагом (`bpSyntaxEnabled`, `bpToolSelectSearch`, `bpToolNodeSearch`, `bpToolBrokenLinks`). Отсутствие ключа = инструмент включён (совместимость со старыми установками). Сканер битых ссылок (`bp-inject-scanner`) и слушатель `bp-broken-scan-done` инжектятся только при включённой подсветке нод с ошибками.
- **`popup.js`:** обработка тумблеров обобщена — цикл по `input[data-tool]`, ключ хранится в `data-tool`. Переключение пишет в `chrome.storage.local`, просит обновить страницу.

## 1.6.0

- **Поиск по нодам в правой панели дизайнера БП.** Фильтрует группы и отдельные ноды (`tr[style*="height"]` внутри `.swftoolboxgrouplist`) по вхождению подстроки. Escape сбрасывает фильтр.

- **Поиск в select-списках разделён по типу:** overlay для listbox (`size > 1`), DOM-insertion для обычных дропдаунов — исправлено перекрытие штатного интерфейса.

## 1.5.1

- **Поиск в списке: ширина поля теперь совпадает с шириной select-а.** Убрано `width: 100%` из CSS; ширина устанавливается через JS (`ResizeObserver` на select). Исправляет визуальный съезд поля поиска на формах с узкими дропдаунами.
- **Красный значок ошибки на ноде: исправлено обнаружение диалога.** `looksLikeActivityDialog` теперь проверяет точное совпадение токена класса (`/(^| )bx-core-window( |$)/`), а не substring. Раньше дочерние элементы с классами типа `bx-core-window-header` ложно совпадали и `watchDialogForErrors` вызывался 8+ раз подряд.
- **Красный значок: исправлено обнаружение ноды.** `findActivityNode` теперь находит контейнер активити по классу `activityhead` (заголовок ноды, всегда на 1-м уровне от иконки шестерни) и возвращает его родителя (`activity activity-modern`). Ранее regex не покрывал классы BP-дизайнера без префикса `bizproc`.

## 1.5.0

- **Поиск в select-списках.** Рядом с каждым `<select>` (≥ 5 вариантов) на страницах БП появляется поле «Поиск в списке…». Фильтрация по вхождению подстроки, выбор мышью или клавишами ↑↓ Enter, Escape закрывает выпадашку. Не модифицирует сам `<select>` — выбор устанавливается через `.value` + `Event('change')`. Дропдаун прикреплён к `document.body` (position:fixed), не ломает layout формы.
- **Красный значок ошибки на ноде БП.** При открытии настроек активити отслеживается появление баннера Битрикса «В роботе используются отсутствующие или недоступные поля/переменные/константы». Если баннер обнаружен — на ноде, по которой кликнули, появляется красный кружок с «!» (position:absolute, top-right угол). Значок остаётся до перезагрузки страницы. Распознаются ноды по классам `bizproc-*`, `automation-*` и атрибутам `data-activity-id`, `data-robot-id`, `data-cid`.
- Версия поднята в `manifest.json`.

## 1.4.0

- **Ребрендинг в «5 УГЛОВ. Инструменты интегратора Bitrix24».** Папка переименована `fivecorners.bitrix24-bp-syntax-for-browser` → `fivecorners.integratorstoolbox`; продукт спозиционирован как набор инструментов интегратора, подсветка синтаксиса БП — первый инструмент. Обновлены `manifest.json` (name/description/title), README, popup/options titles, CLAUDE.md.
- **Заведён git-репозиторий.** Initial commit, ветка `main`, remote `github.com/5corners-ru/fivecorners.integratorstoolbox` (registered в Палыче, id=36).
- **Полная переработка архитектуры подсветки.** Отказ от оверлейного подхода (contenteditable / прозрачный textarea) — фундаментальная проблема несовпадения курсора и текста из-за различий в движках рендеринга оказалась неустранимой.
- **Новый подход — кнопка по требованию:** рядом с каждым `textarea` появляется маленькая кнопка `</>` (position:fixed). Клик открывает панель с подсвеченным текстом поверх textarea (position:fixed). Ещё клик или Escape — закрывает панель, фокус возвращается в textarea. Textarea не модифицируется вообще.
- **Добавлен background.js** (service worker): при перезагрузке расширения восстанавливает динамическую регистрацию content scripts для коробочных порталов (`chrome.runtime.onInstalled` / `onStartup`).
- **Исправлена кнопка «Добавить текущий портал»** в popup: после выдачи разрешения скрипт немедленно инжектируется в активную вкладку без перезагрузки страницы.
- **Упрощены стили:** удалены все overlay-классы, только `.bp-hl-btn` и `.bp-hl-panel`.
- Страница детальных настроек стала шире (max-width 640→960px).

## 1.2.3 (текущая стабильная)

- **Подход для полей из textarea:** один contenteditable div (`.bp-syntax-editable`) с подсвеченным HTML; скрытый textarea хранит значение для формы. Курсор и перенос строк совпадают с видимым текстом.
- Рамка у contenteditable: копирование границы из исходного textarea, цвет по теме (светлая/тёмная).
- Enter в contenteditable: `preventDefault`, `insertLineBreak` или `insertText('\n')`, затем обновление подсветки.
- ResizeObserver на textarea — начальные размеры обёртки; ResizeObserver на родителе обёртки — подстройка при изменении размера контейнера.
- Исключение поля «Заголовок» (id=`bpastitle` или name=`title`) из подсветки.
- **Ресайз перетаскиванием:** не реализован. Попытки (1.2.4–1.2.7) откатаны: ручка ресайза + изменение размеров обёртки приводили к конфликтам (двойная обёртка из-за attachHighlightToContentEditable, рассинхрон рамки и поля). Текущая версия без ручного ресайза.
