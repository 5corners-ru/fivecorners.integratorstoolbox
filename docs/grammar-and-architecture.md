# Грамматика подсветки и архитектура расширения

Краткое описание для разработчиков: как устроена подсветка и какие токены распознаются. **Актуально для версии 1.4.0.**

## Архитектура

### Файлы

| Файл | Назначение |
|------|-----------|
| `content.js` | Content script: токенайзер, кнопка `</>`, панель подсветки, DOM-сканирование |
| `styles.css` | Стили кнопки (`.bp-hl-btn`) и панели (`.bp-hl-panel`) |
| `background.js` | Service worker: восстанавливает регистрацию content scripts при рестарте расширения |
| `popup.js` | Быстрое добавление текущего сайта, переключатель on/off |
| `options.js` | Детальное управление списком порталов, настройка темы и цветов |

### Жизненный цикл

1. **Content script** внедряется на страницы, совпадающие с `manifest.json` (облачные Bitrix24) или динамически зарегистрированные из `chrome.storage.local` (коробка).
2. **`isTargetPage()`** проверяет hostname и список кастомных origins.
3. **`scanAndAttach(root)`** обходит все `textarea` на странице (кроме `#bpastitle` / `name=title` и скрытых), вызывает `attachHighlightButton(textarea)` для каждого нового поля.
4. **MutationObserver** следит за появлением новых элементов (открытие модалок) и повторно запускает `scanAndAttach`.
5. Дополнительные запуски `scanAndAttach` через 300, 1000, 2500 мс после загрузки страницы — страховка для полей, появляющихся с задержкой.

### Кнопка по требованию (`attachHighlightButton`)

Textarea **не модифицируется**. Рядом с ней:

- Создаётся кнопка `</>` (`button.bp-hl-btn`, `position:fixed`) и добавляется в `document.body`.
- Позиция кнопки вычисляется через `getBoundingClientRect()` при каждом скролле и ресайзе (`scroll`/`resize` listeners).
- По клику на кнопку открывается панель (`div.bp-hl-panel`, `position:fixed`) поверх textarea с теми же координатами и размером.
- Панель содержит `<code>` с HTML-разметкой от `highlightToHtml(textarea.value)`.
- Закрытие: клик по панели или `Escape`. После закрытия фокус возвращается в textarea.
- При удалении textarea из DOM (`!document.contains(textarea)`) кнопка и панель удаляются через `destroy()`.

### Service Worker (`background.js`)

Динамически зарегистрированные content scripts (через `chrome.scripting.registerContentScripts`) **сбрасываются при перезагрузке расширения**. `background.js` восстанавливает их при событиях `onInstalled` и `onStartup`, читая список origins из `chrome.storage.local`.

## Грамматика (токены)

Токенайзер `tokenize(text)` обходит строку слева направо; приоритет определяется порядком проверок:

| Токен | Пример | Ключ цвета |
|-------|--------|------------|
| Строка в двойных кавычках | `"текст"` | `stringDouble` |
| Строка в одинарных кавычках | `'текст'` | `stringSingle` |
| Двойная открывающая скобка | `{{` | `brace` |
| Двойная закрывающая скобка | `}}` | `brace` |
| Открытие выражения | `{=` | `brace` |
| Одиночные фигурные скобки | `{`, `}` | `brace` |
| Круглые скобки | `(`, `)` | `paren` |
| Квадратные скобки | `[`, `]` | `bracket` |
| Запятая | `,` | `comma` |
| Двоеточие | `:` | `colon` |
| Ключевые слова | `Document`, `Template` (по границе `\b`) | `keyword` |
| Остальной текст | идентификаторы, пробелы, числа | `other` |

Строки поддерживают экранирование `\"` / `\'`. Ключевые слова ищутся по `\b`, чтобы не подсвечивать часть идентификатора (`MyDocument`).

### Постобработка токенов (`classifyTokens`)

После токенизации:
- Содержимое между `{{` и `}}` (до `=`) помечается как `variable`.
- Токен `other`, за которым следует `(`, переклассифицируется в `function`.

### Цвета

Два встроенных палитры (`PALETTE.light` / `PALETTE.dark`). Переопределяются через `customColors` из `chrome.storage.local` (`bpSyntaxColors`). Активная тема (`bpSyntaxTheme`) применяется при открытии панели.
